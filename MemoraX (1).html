What is cache memory?

A cache is a small, very fast memory that sits between the processor and main memory. It keeps copies of recently used data so the processor does not have to wait for the slower main memory every time. MemoraX lets you see this happen instead of just reading about it.

Hit

The block you asked for is already in the cache. The data comes back immediately.

Miss

The block is not in the cache. It is fetched from main memory and stored, possibly replacing an older block.

Hit rate

Hits divided by total accesses. The higher it is, the better the cache suits your access pattern.

How an address is split

Every address is divided into three fields. MemoraX colors them the same way everywhere.

Tag

Identifies which block of memory is stored in a cache line. Compared on every lookup.

Index

Chooses which set in the cache to search.

Offset

Picks the exact byte inside the block.

What you can experiment with

Change the setup and see how the hit rate responds.

Mapping

Direct-mapped, 2-way, 4-way or fully associative. More ways means fewer conflicts.

Replacement

LRU evicts the least recently used block. FIFO evicts the oldest one loaded.

Sizes

Cache sizes of 128, 256 or 512 bytes with block sizes of 8, 16 or 32 bytes.

Access patterns

Sequential, loop, conflict and random examples, or addresses you add yourself, with a full hit and miss record for each.

Using the simulator

  1. Choose a cache size, block size, mapping and replacement policy.
  2. Add your own addresses (decimal, hex or binary), or load an example list.
  3. Press Step to run one access, or Play to run them all.
  4. Watch the address split, the set highlight, and the hit rate update, then check the history and address report to see which addresses hit or missed.

Cache simulator

Choose a cache, add the memory addresses you want to access, then run them. Every access is recorded as a hit or a miss, with the address, set and way involved.

Cache setup

Changing any option clears the cache and restarts the run. Your address list is kept.

Memory addresses

Use decimal (64), hex (0x40) or binary (0b1000000), from 0 to 65535. Separate several addresses with spaces or commas. Removing an address restarts the run.
